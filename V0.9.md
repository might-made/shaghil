## Post-launch fix — EXACT-fidelity product compositing retained the source photo's original background

Founder Live QA: selecting a saved Product Library item (Wash Me) with "المنتج الأصلي" (EXACT fidelity) correctly preserved the exact product artwork, but composited the entire source photo rectangle — including its original white/light studio background — onto the newly generated scene, on both first generation and "تغيير الخلفية".

**Root cause:** `composeVisual()`'s exact-fidelity branch (`lib/visual-canvas.mjs`) never isolated the product from its background at all — it decoded and drew the full stored `Blob` as-is. There was no foreground/background segmentation anywhere in the codebase.

**Fix:** added `lib/background-removal.mjs`, a client-side product isolation step using a purpose-built semantic segmentation model (loaded lazily from a CDN, no server call, no per-image API cost, no new backend) that edits only the alpha channel of pixels it identifies as background — it never repaints or regenerates the product's own pixels, so EXACT fidelity's guarantee (the supplied product artwork, not an AI approximation) still holds. A product photo that already has real transparency (checked via its actual alpha channel, never pixel color, so a light/white opaque product like Wash Me is never mistaken for already-transparent) passes through unchanged. Isolation results are cached per product id + image size for the session, and a replaced product photo never reuses a stale mask. On isolation failure, compositing falls back to the original image and reports a clear warning rather than crashing or silently reproducing the bug. `composeVisual()` gained one optional `report` parameter for this; every existing caller is unaffected by the default. Both the initial generation and `تغيير الخلفية` share the exact same `composeVisual()` call, so both are fixed by the same change. Product Library/export/import storage and schema were completely untouched — isolation happens transiently at compose time only. Two now-inaccurate copy strings that told users to pre-supply a transparent PNG (since the background wasn't removed automatically) were updated to describe the new automatic behavior.

Added `scripts/qa-v09-background-isolation.mjs` (wired into `npm run qa`): opaque-background products are isolated; already-transparent products pass through unchanged; a light/white opaque product is never mistaken for already-transparent; isolation failures degrade safely with a warning instead of crashing; `تغيير الخلفية` uses the identical corrected pipeline; EXACT mode still never sends the product image to the generation model; Visual History persists the corrected composite. Verified this suite fails against the pre-fix code (reproducing the exact reported symptom — the raw JPEG rectangle drawn instead of the isolated PNG) and passes with the fix restored.
