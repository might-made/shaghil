# SHAGHIL V0.9 — Pilot Readiness

Starting point: Founder-QA-passed, frozen V0.8 `af343360902a2e1717c17b3d1cdbb568b00668cb`. Work belongs only to `shaghil-v0.9`; no merge or Production promotion; `shaghil-v0.8` remains as closed/frozen as `shaghil-v0.6`/`shaghil-v0.7`. Version: `0.9.0`.

V0.9's single product objective, per the Founder-approved Product Readiness Audit: **make the already-working V0.8 product safe and clear enough for a small, Founder-personally-onboarded external pilot (3–5 users)** — not new AI capability, not a redesign. No seventh engine, no backend/auth/accounts, no video generation, no Salla/Zid, no architecture change.

## P0 — Lightweight first run

The `#setup` screen previously presented Business Brain (8 fields), Brand Brain and Product Library as one undifferentiated form before any value was reachable. It now separates:

- **المعلومات المطلوبة للبدء** — only the 3 fields already required for text generation (`name`/`product`/`customer`), with a dedicated **ابدأ الآن** button that calls the existing `saveBrain()` directly — no new save path, no new validation, no new storage shape.
- **تفاصيل إضافية (اختياري)** — the remaining Business Brain fields (`category`/`location`/`price`/`tone`/`objective`), clearly labeled optional.
- **Brand Brain** and **مكتبة المنتجات** headings now say "اختياري — يمكن إضافتها لاحقًا"; nothing about their capability changed.
- The original **حفظ كل التفاصيل والبدء** button (was "حفظ والبدء") still exists, unchanged in behavior (`Visual.saveProject()`), for anyone who wants to fill everything in one pass.

No field id, storage key, or save function changed. A pre-V0.9 Business Brain (all 8 fields) still populates every field exactly as before when reopening `setup()` for editing — verified by regression.

## P0 — Local data safety

A new dismissible notice (`#localDataNotice`) appears the first time a user reaches `#setup`, in plain Arabic with no technical storage terms (no "IndexedDB"/"localStorage"): it explains data lives on this device/browser only, won't carry over automatically on a device/browser change, and that Workspace Export protects the work. A single **فهمت** click hides it permanently (`localStorage['localDataNoticeDismissed']`) — it never reappears once dismissed, and it is never shown as a repeating/intrusive prompt. The existing Export/Import UI (already reachable from both the empty setup screen and the Business Brain summary since the V0.8 post-launch fixes) is unchanged.

## P0 — Visual generation wait UX

Visual Studio's generation status (`visualStatus`/`visualResultStatus`) previously showed one static sentence for the entire wait. It now ticks a live elapsed-time counter every second ("جارٍ إنشاء صورة واحدة… (12 ثانية) — قد يستغرق ذلك حتى دقيقتين ونصف") for as long as the request is in flight, and a CSS spinner (already defined, previously unused) becomes visible next to the status text while busy and hides again on completion or error. This is real elapsed time, never a fabricated percentage. The request/response flow, `payload()`, `composeVisual()` and `/api/visual` itself are byte-for-byte unchanged — this is a status-line and `lock()` change only.

## P0 — First-value guidance

A small, dismissible **ابدأ من هنا** card now appears on Home the first time a user reaches it, pointing at the two lowest-setup-friction engines — **سوّ محتوى** and **رد على عميل** — with direct buttons into each. One **إخفاء** click hides it permanently (`localStorage['firstValueHintDismissed']`). This is a recommendation card, not a tutorial/wizard — no forced steps, no blocking overlay.

## P0 — Mobile readiness

No CSS or layout logic was changed beyond reusing the existing `.card`/`.form`/`.actions`/`.btn` classes for the new notice/hint elements, so the existing `@media(max-width:700px)` responsive rules apply to them unchanged. This release does **not** claim a mobile PASS — that verification is explicitly reserved for Founder live QA on the deployed Preview, per the Founder's instruction not to claim mobile readiness from automated CSS inspection alone.

## Regression coverage

- Quick start with only the 3 required fields reaches Home and persists exactly those fields; the button is verified to call the existing `saveBrain()` (no new/duplicate save path).
- A pre-V0.9, fully-populated legacy Business Brain still populates every field correctly when reopening `setup()` — proving existing V0.8 workspaces continue working unchanged.
- The local-data notice shows on first setup, contains no technical storage terminology, and never reappears once dismissed (including on a later `setup()`/"تعديل" visit).
- The first-value hint shows once on Home, points at the two intended engines, and never reappears once dismissed.
- Visual Studio's generation wait: the spinner is hidden before generation, visible throughout, and hidden again after; the status text contains a real elapsed-second count, contains no `%` character, and changes over a 1+ second window while a request is deliberately held open — proving the status is live, not static, without asserting any specific fake progress value.

All five checks were verified to fail against the pre-fix markup/code (temporarily reverting `index.html`/`lib/visual-studio.mjs` and re-running the new test file alone reproduces a hard failure on the very first assertion) and pass with the fix restored. The complete existing V0.5–V0.8 suite (structural checks, server engines, frontend integration, Visual Studio, campaign packs, workspace transfer, history rendering, etc.) was re-run in full and passes unchanged.
