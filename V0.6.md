## Checkpoint and branch safety

Started from the Founder-approved V0.5 commit `35c118a2befa8d0630f3ec3445874679c997d933` on new branch `shaghil-v0.6`. Development belongs only on that branch. Do not merge into `main`, alter `shaghil-v0.5`, or promote a deployment without Founder approval.

## Architecture

- Existing Business Brain and all six text engines remain in place. The same setup screen now includes Brand Brain.
- Business Brain text retains its existing localStorage key. Brand Brain metadata, logo and up to two reference images are stored atomically in IndexedDB as structured data and binary Blobs. Visual history also uses IndexedDB, capped at ten entries; original background, composited PNG, business/brand snapshots, source output, settings and creative direction are retained.
- No large image data is written to localStorage. No new cloud database or object store is needed. Files are validated and resized before storage; logo PNG preserves transparency and proportions. Inputs accept PNG/JPEG/WebP, up to 8MB before normalization and 700KB afterward.
- Assets are local to this browser and origin. Different preview URLs/devices do not share them. Browser data deletion or storage eviction can remove assets. Download important work. Storage failures are reported, and a generated image can still be downloaded from memory.

## Visual flow

Content / Campaign / Offer result → **اصنع التصميم** → select a source idea/day → choose format/style/text mode → generate one image.

The source picker extracts existing Markdown sections and paragraphs. Selecting an exact substring of the source text before opening Studio is also supported. A full source snapshot accompanies the selected excerpt; users do not rebuild a prompt. Some unusual Markdown formats may need selection of the relevant text instead of the automatic section picker.

Copy, WhatsApp and Reel do not receive a visual-generation button. Home still contains exactly six engines.

## Image API

`POST /api/visual` validates and allowlists business fields, brand colors, source engines, source excerpt, formats, modes, text modes and raster attachments. It constructs the image prompt on the server. The existing `OPENAI_API_KEY` is used only on the server.

Default model: **gpt-image-2.5-flare**, medium quality. Optional server environment variable: `OPENAI_IMAGE_MODEL`. An override must support the same Image API parameters and custom dimensions. No automatic model fallback is used.

- Without references: `client.images.generate`.
- With references: `client.images.edit`, with actual raster files.
- One request, `n: 1`; SDK retries disabled; no background generation.
- Model dimensions: 1024×1024, 1024×1280, 864×1536.
- Final PNG dimensions: 1080×1080, 1080×1350, 1080×1920.
- Image function maximum duration: 180 seconds; SDK timeout: 150 seconds. Text/health duration remains 30 seconds.
- Server returns one JPEG as base64 in the HTTP response; the browser immediately turns it into a Blob. That transport encoding is not persisted in localStorage.

References: [OpenAI image generation guide](https://developers.openai.com/api/docs/guides/image-generation), [GPT Image 2.5 Flare](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare).

## Logo and Arabic text

The image model receives no logo bytes and is told to generate a clean image without typography or logos. The original uploaded logo is composited on a browser canvas with preserved aspect ratio, alpha and safe margins.

Text defaults to **بدون نص**. Simple/full modes prefill available source copy/CTA for user review, and canvas draws the approved Arabic text with browser font shaping. Text is fitted within a bottom panel. Overlong text reports an error rather than clipping; if composition fails after a paid generation, the available visual is preserved without text for further editing.

Text editing, removing text and changing size are local operations with no image API charge. Resizing fits the original image without cropping; if the aspect ratio changes, brand-color padding may appear. A fresh generation in a chosen format uses that format in the model request.

Second version keeps the business, brand/assets, selected task and settings from the generated visual's snapshot. The server chooses a different composition direction from the previous one. Premium and Minimal variants change the mode explicitly. Different direction prompting improves variation but cannot guarantee model behavior.

## Brand safety and costs

Prompts prohibit invented SKUs, variants, discounts, urgency, claims, awards, reviews, certifications and pricing. Average price ranges are context, not exact SKU claims. All visuals are labeled conceptual, even with references; exact product reproduction is not guaranteed. Founder must check product fidelity and claims before publishing.

Each Generate, Second version, Premium or Minimal action calls the billable image API once. In-flight controls prevent repeated clicks within a page. SDK retries are disabled so failures do not automatically purchase another image. A failed/timeout response can still be billable upstream. This MVP has no distributed deduplication, authentication, per-user quota or billing enforcement; retain protected previews and set provider budget limits before any public release. No production or account settings were changed.

## Automated QA

Run `npm install` and `npm run qa` on Node 20+.

- V0.5 regression suite: all six engines; Brain persistence; optional inputs; WhatsApp validation; generation, copying, refinements, second version, history, escaped content, duplicate clicks and navigation races.
- V0.6: all 45 format × visual mode × text mode request combinations, allowed source engines, actual reference-file forwarding, logo exclusion from model input, validation, missing key and failure behavior, one-image/no-retry configuration.
- IndexedDB tests: saved brand colors/style/assets, Blob retention, visual metadata and ten-entry pruning.
- Browser-controller tests: integrated setup, automatic context, idea selection, no-text default, second-version snapshots, local overlay actions, history, duplicate-click guard and client credential checks.
- Compositor geometry: all three ratios and text modes, logo proportions/margins and long-text bounds.

QA uses simulated model responses. No live OpenAI text or image request was made during V0.6 QA. Automated DOM tests mock raster decoding; a real-browser smoke test additionally verifies actual logo upload, persisted identity, content-to-Studio navigation, Arabic canvas rendering, local overlays, second version, saved history reload and a 390px mobile viewport.
